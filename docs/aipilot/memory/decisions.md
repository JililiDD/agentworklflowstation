# Decisions

## 2026-10-13 自建薄引擎

- **选择：** 自建工作流引擎。不基于现成平台，例如 n8n、Kestra 或 Dify。也不基于编码 agent 工作流工具，例如 rayspec。
- **理由：** 现成工具只能省掉调度和续跑，省不掉 agent 节点的执行。任意嵌套的循环、写入互斥、git 检查点和同步问答，现成平台都无法表达。
- **切换条件：** 如果调度器的实际工作量超过估算的 2 倍，就改用 TypeScript 工作流库做底座，例如 Mastra 或 LangGraph.js。
- **来源：** handoff 文档，以及 2026-10-13 的讨论。

## 2026-10-13 runner 层不依赖引擎

- **选择：** 引擎只通过 `StepRunner` 接口执行节点。所有节点运行时的调用只出现在 runner 层。
- **理由：** 更换运行时或升级 pi 时，只需要改 runner 层。runner 层不依赖引擎，以后可以包装成其他平台的节点。

## 2026-10-13 使用 TypeScript

- **选择：** 引擎、runner 和界面都用 TypeScript，运行在 Node 上。
- **理由：** pi 的 SDK 和界面都是 TypeScript，全程只用一种语言。
- **放弃：** Java/Spring 编排加 pi 子进程。只有接入现有 Java 系统时才值得。

## 2026-10-13 节点运行时使用 pi

- **选择：** 用 pi 执行 agent 节点。
- **理由：** pi 现成支持多家模型、thinking level 和 skill。
- **放弃：** Claude Agent SDK，因为它只支持 Claude。也放弃直接调用各家 API。
- **注意：** pi 的若干能力尚未验证。验证清单见 handoff 文档。

## 2026-10-13 运行状态保存在文件中

- **选择：** 运行状态保存在运行目录的文件中，不用数据库。
- **理由：** 文件可以直接查看，便于调试。
- **放弃：** SQLite。多用户时再考虑。

## 2026-10-13 节点之间靠产物交接

- **选择：** 每个节点使用独立的会话。节点之间通过产物文件和共享工作区交接。
- **理由：** 跨公司切换模型时，没有上下文兼容问题。
- **放弃：** 共享对话历史。

## 2026-10-14 测试策略

- **选择：**
  - 自动化测试不调用真实模型，全部使用 FakeRunner。
  - 核心界面流程用 Playwright 做自动化测试，测试中的运行由 FakeRunner 驱动。
  - 真实模型只在各阶段的手动验收中运行。验收运行不设费用上限。
- **理由：** 自动化测试要免费、结果确定。真实模型的行为不稳定，而且每次都要花钱。
- **约束：** 验收可用的提供方是 Claude 订阅、OpenAI 和 Google。没有 Anthropic API key。
- **来源：** 用户在路线图规划时的回答。

## 2026-10-14 测试分档和工具链

- **选择：**
  - 包管理用 npm workspaces。测试用 Node 自带的 `node:test`。类型检查用 `tsc`。lint 和格式检查用 Biome。
  - 快速档：`npm run typecheck && npm run lint && npm test`。
  - 完整档：对每个改动涉及的包运行 `npm run build -w <包名>` 和 `npm test -w <包名>`。
- **理由：** 复用已安装的 npm 和 Node 自带功能，依赖最少。pnpm 没有安装。
- **来源：** 用户在第 1 阶段计划问题中确认。

## 2026-10-14 真实模型验收优先用便宜的模型

- **选择：** 真实模型的验证和验收运行，优先使用各家便宜的模型，例如 OpenAI 的 `gpt-5.6-luna` 和 Claude Haiku。只有验证内容需要更强的模型时，才换用更贵的模型。
- **理由：** 降低花费和订阅额度的消耗。Claude 经 pi 使用时按 token 计费。
- **来源：** 用户在第 1 阶段计划审阅中的批注。

## 2026-10-15 锁定 pi 1.3.0

- **选择：** 全局 pi 和 runner 的 SDK 都用 `@earendil-works/pi-coding-agent` 1.3.0。
- **理由：** npm 当前最新是 1.3.0。用户要求全局和项目都升到该版本。
- **影响：** 本条取代 Phase 1 Plan 中锁定 1.2.0 的决定。
- **来源：** 用户在 2026-10-15 的回复。

## 2026-10-15 Google Gemini 订阅可用，Phase 1 仍不做

- **选择：** Phase 1 真实模型验证仍只用 Anthropic 和 Codex。Google 留给以后的阶段。
- **理由：** 本机已有 Google Gemini 订阅，经 antigravity oauth 可用。用户选择不扩大 Phase 1 范围。
- **影响：** 本条更新「2026-10-14 第 1 阶段只验证 Anthropic 和 OpenAI」中 Google 不可用的理由。该条的范围不变。
- **来源：** 用户在 2026-10-15 选择 (a)。

## 2026-10-14 第 1 阶段只验证 Anthropic 和 OpenAI

- **选择：** 第 1 阶段的真实模型验证只用 Anthropic（Claude 订阅）和 OpenAI（ChatGPT 订阅）。Google 暂不使用。
- **理由：** pi 不支持 Google 的订阅登录，用户暂时不申请 Gemini API key。两家公司已经能验证"不同节点使用不同公司的模型"。
- **影响：** 本条收窄了"2026-10-14 测试策略"中可用提供方的范围。该条的其余内容不变。
- **来源：** 用户在第 1 阶段计划审阅中的回复。

## 2026-10-15 Phase 4 共享 pi 订阅凭证

- **选择：** 平台通过 pi SDK 提供订阅登录入口。平台与 pi CLI 共用本机 `auth.json`，不另存 OAuth token。
- **理由：** 用户希望在平台里登录订阅账号，并让登录结果可供节点使用。
- **约束：** 登录状态只暴露非敏感元数据；runner 必须沿用 pi 的锁保护刷新机制，不能覆写整个凭证文件。
- **来源：** 用户在 Phase 4 规划时选择共享凭证方案 A。

## 2026-10-15 Phase 4 架构依赖测试

- **选择：** 加入 service、engine、runner 的依赖方向自动测试。
- **理由：** 服务阶段增加 HTTP 与认证边界，需要防止 pi SDK 调用泄漏到引擎。
- **来源：** 用户在 Phase 4 规划时选择加入。

## 2026-10-15 Phase 4 本机数据与 CLI 入口

- **选择：** 用 `aipilotagent serve` 启动本地服务。工作流库、非敏感设置和运行记录保存在 `$XDG_DATA_HOME/aipilotagent`，默认 `~/.local/share/aipilotagent`。
- **理由：** 服务数据与目标仓库及 pi 凭证分离，符合运行记录不进入目标仓库的约束。
- **限制：** 真实启动前仍须验证数据目录不在目标 git 仓库内；凭证继续保存在 pi agent 目录。
- **来源：** Phase 4 工作项计划的实现选择。

## 2026-10-15 Phase 5 前端底座

- **选择：** 浏览器运行视图使用 React、Vite 和 TypeScript。Playwright 验证核心浏览器流程。
- **理由：** 实时运行状态、节点抽屉与 Inbox 共享状态；Phase 6 可复用界面组件。
- **来源：** 用户在 Phase 5 规划时选择方案 A。

## 2026-10-15 Phase 5 问答历史与秘密回答

- **选择：** 非秘密问答正文保存在本机运行目录。用户标记为秘密的回答仅保存已回答状态，不保存正文。
- **理由：** 页面刷新后保留非秘密问答历史，同时避免持久化用户主动标记的秘密内容。
- **来源：** 用户在 Phase 5 规划时选择方案 A。
