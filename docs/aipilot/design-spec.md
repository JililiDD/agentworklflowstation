# aipilotAgent 设计规格

Version 1, 2026-10-13. Each later version states what changed and why.

## 1. Design Summary

aipilotAgent 的界面是一个冷静、精确的开发者工具。结构参考 n8n，视觉参考 Linear 和 VS Code。画布上只有状态带色相，其他元素都用中性色和墨色。连线上标出节点之间流动的产物，这是界面最有辨识度的一处。用户在浏览器审阅中批准了样稿 v2：`design-assets/2026-10-13-ui-direction/ui-direction-v2.html`。本规格以 v2 为准。

## 2. Product Personality

- 产品像一件冷静、精确的开发者工具。它紧凑，状态一眼可见，没有多余装饰。
- 产品优先保证可信：用户随时能看清每个节点在做什么、花了多少、在等什么。
- 平台以工具的口吻说话，不拟人。agent 的话原样显示。
- 产品不能有三种感觉：花哨的 AI 风格、笨重的企业软件和玩具感。

## 3. Reference Products

### 3.1 Structural References

- **n8n**：左侧导航和节点库，中间是画布。编辑工作流和查看运行用同一张画布，运行时节点上叠加状态。
- 与 n8n 的差别：属性面板是右侧抽屉，不是盖住画布的大浮层。

### 3.2 Visual References

- **Linear**：中性色、细边框、克制的强调色和清晰的字重层级。
- **VS Code**：紧凑的工作台布局、底部的 Problems 面板，以及等宽字体用于代码类内容。

### 3.3 Interaction References

- **n8n**：在画布上拖拽节点、连接节点。
- **VS Code Problems 面板**：列出校验错误，点击后跳到出错的位置。
- **命令行选择题**：问答选项可以按数字键选择。

## 4. Anti-References

- **花哨的 AI 风格**：紫蓝渐变、发光效果、装饰性的聊天气泡。
- **笨重的企业软件**：密集的工具栏、弹窗里套弹窗。
- **玩具感**：大圆角、卡通插图和 emoji。
- **落选的样稿 v1**：`design-assets/2026-10-13-ui-direction/ui-direction.html`。它的这些做法不采用：
  - 紫色强调色；
  - 全大写的字段标签；
  - 带边框的对话框式问答。
- **thinking 刻度**：v2 曾用 5 格刻度表示 thinking level。用户认为文字更直观，因此不采用刻度。

## 5. Information Architecture

### 5.1 Main Object

用户管理两类对象：

- **工作流**：在画布上搭建，保存在工作流库中。
- **运行**：工作流在一个目标 git 仓库上的一次执行。

### 5.2 Top-Level Areas

左侧导航栏有四个区域：

- **Workflows**：工作流列表。打开一个工作流，进入画布编辑器。
- **Runs**：运行列表。打开一个运行，进入运行视图。
- **Inbox**：所有运行中等待回答的问题和等待审批的节点。
- **Settings**：skill 来源目录和模型凭证。

### 5.3 Navigation Model

- 导航栏常驻在最左侧，只显示图标，悬停时显示名称。
- 当前区域的图标有浅色底，左侧有一条墨色短竖线。
- 顶部栏左侧显示面包屑，例如 `Workflows / feature-dev`。
- 待处理项和问题列表中的条目都能直接跳到对应节点。

### 5.4 Always-Visible Information

- 导航栏和 Inbox 的数量徽标。
- 编辑器中的问题列表。没有错误时，列表折叠为一行标题。
- 运行视图中的运行头部：状态、已用时间、费用和预算、人工介入次数，以及节点进度。

## 6. Core Screens

- **工作流编辑器**：有样稿。顶部栏、节点库、画布、问题列表和属性抽屉。
- **运行视图**：有样稿。顶部栏、运行头部、只读画布和节点详情抽屉。
- **工作流列表**：每行显示名称、节点数和最近修改时间。列表为空时，显示空状态。
- **运行列表**：每行显示工作流名、运行编号、目标仓库、状态、已用时间和费用。
- **Inbox**：每行显示运行名、节点名、类型（问题或审批）和等待时长。
- **Settings**：分两组，分别是 skill 来源目录和模型凭证。

没有样稿的四个画面沿用本规格的布局和视觉系统。

## 7. Layout System

### 7.1 Workspace Layout

工作流编辑器从左到右依次是：

| 区域 | 宽度 | 内容 |
| --- | --- | --- |
| 导航栏 | 52px | 四个区域图标 |
| 节点库 | 76px | Agent、Command、Group、Foreach |
| 画布 | 剩余宽度 | 节点、框和连线。底部是问题列表，高 104px。 |
| 属性抽屉 | 384px | 选中节点的属性 |

- 顶部栏高 48px，横跨画布和抽屉。
- 运行视图没有节点库。顶部栏下方是运行头部，高 46px。
- 画布中的流程从上到下排列。连线从上游节点的底部连到下游节点的顶部。

### 7.2 Panel Behavior

- 单击节点时，右侧抽屉显示它的属性或详情。画布保持可见，也可以继续操作。
- 点击抽屉右上角的 ×，或按 Esc，抽屉关闭。
- 问题列表可以折叠。
- 组节点和 foreach 节点的框可以折叠。折叠后只显示类型、名称和进度。

### 7.3 Responsive Rules

- v1 只支持桌面浏览器，窗口宽度至少 1280px。
- 不做窄屏和移动端适配。

## 8. Visual System

### 8.1 Theme

- 提供亮色和暗色两套主题，默认跟随系统设置。
- 所有颜色都定义为变量，两套主题共用同一组变量名。

### 8.2 Color

色相只表示状态。界面框架、选中状态和主要按钮都用中性色和墨色。

| 角色 | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| base | `#f4f5f7` | `#16181b` | 画布和页面底色 |
| panel | `#ffffff` | `#1c1f23` | 导航栏、顶部栏、抽屉 |
| raised | `#ffffff` | `#22262b` | 卡片、输入框、按钮 |
| sunken | `#eef0f3` | `#1a1d21` | foreach 框底色、选中的导航项 |
| line | `#e2e5e9` | `#2c3137` | 分隔线 |
| line-strong | `#c8cdd4` | `#3c434c` | 卡片、框和控件的边框 |
| ink | `#1b1f24` | `#eef0f2` | 正文、强调色：选中描边和主要按钮 |
| muted | `#5f6b7a` | `#9aa4b0` | 次要文字、标签 |
| run | `#2563eb` | `#60a5fa` | 运行中 |
| ok | `#15803d` | `#4ade80` | 成功、已批准、已产出 |
| fail | `#dc2626` | `#f87171` | 失败、校验错误 |
| wait | `#b45309` | `#fbbf24` | 等待人工：等回答或等审批 |
| skip | `#8a94a3` | `#6f7985` | 等待上游、已跳过 |

- 每种状态都同时用图标表示，不只靠颜色区分。
- 强调色只用墨色，只用在选中状态和主要按钮上。

### 8.3 Typography

- 界面文字用系统字体。
- 等宽字体只用于代码类内容：模型名、路径、`{{...}}` 引用、命令、日志和 diff。
- 字号：11px 用于提示，12px 用于次要文字，13px 用于正文，14px 用于标题。
- 字重：400 用于正文，500 用于按钮和标签页，600 用于标题和节点名。
- 标签用句首大写，不用全大写。
- 数字用等宽数字（tabular numerals），例如时间和费用。

### 8.4 Density

节点卡片是中等密度，宽 236px，高 120px。卡片从上到下显示：

1. 类型图标、名称，以及右上角的标记图标。
2. 模型名和 thinking level 文字，例如 `claude-sonnet-5-5 · medium`。
3. 任务文本的前两行。
4. 编辑器中显示所选 skill，运行视图中显示运行状态和用时。

### 8.5 Radius, Borders, and Depth

- 卡片圆角 5px，框圆角 6px，按钮和输入框圆角 4px。
- 用 1px 边框区分层级。不用阴影，也不用渐变。
- 选中节点用墨色边框加 1px 墨色外描边。
- 运行视图中，卡片左侧有 3px 的状态色条。
- foreach 框背后有两层错开的边线，表示每一项各执行一次。

### 8.6 Icons and Controls

- 图标是 16px 线性图标，线宽 1.5px。
- 节点类型图标：agent 用菱形，命令用命令提示符，组节点用循环箭头，foreach 用叠放的矩形。
- 节点标记图标：可写用铅笔，交互式用对话框，需要审批用盾牌加勾，有执行条件用分支。
- 分段选择器用于少量互斥选项，例如 thinking level 和写权限。选中项用墨色底。
- 开关用于是否交互和是否审批。

## 9. Interaction Model

- **创建节点**：点击顶部栏的"Add node"按钮，或从左侧节点库拖到画布上。
- **连接节点**：从上游节点底部的连接点拖到下游节点。
- **嵌套**：把节点拖进组节点或 foreach 节点的框里。
- **编辑属性**：单击节点，在右侧抽屉中编辑。属性分为四组：Model、Prompt、Behavior 和 Outputs。
- **插入引用**：在任务文本中输入 `{{`，系统列出可用的输入、上游产物和当前项字段。
- **复制和粘贴**：用 Ctrl C 和 Ctrl V 复制粘贴节点或子图。
- **缩放**：用顶部栏的 − 和 + 按钮，或按 Ctrl - 和 Ctrl +。点击比例数字或按 Ctrl 0，画布会缩放到显示整个流程。
- **校验**：搭建过程中实时校验。出错的节点显示红色边框，问题列表列出原因和修正方法。
- **产物连线**：如果下游节点引用直接上游的产物，连线上会显示产物文件名。在运行视图中，已产出的产物标签是实线，并带绿色勾。还没产出的是虚线。
- **查看运行**：运行视图是只读快照。框的标题栏上有切换器，可以查看其他轮次或其他列表项。
- **回答问题**：点击选项、按对应数字键，或在输入框中输入答案。

## 10. Agent / AI UI

### 10.1 AI Entry Point

- agent 只存在于节点中。平台没有全局的聊天窗口。
- 用户通过三个地方和 agent 交互：节点详情抽屉、Inbox 和运行头部。

### 10.2 Execution Visibility

- 节点卡片显示状态图标、状态文字、用时和费用。
- 运行中的节点显示旋转图标和已用时间。
- 运行头部显示整个运行的状态、费用占预算的比例，以及按状态分段的节点进度条。
- 节点详情抽屉有这些标签页：
  - Events：结构化事件列表；
  - Task：实际发出的任务文本；
  - Outputs：产物；
  - Questions：只有交互式节点有；
  - Diff：只有可写节点有。
- 事件列表每行一条，包括时间、类型图标、摘要和用量。点击一行可以展开详情。

### 10.3 Approval, Pause, Cancel, Retry

- **审批**：抽屉中显示节点的产物和 diff，下面是 Approve 和 Reject 按钮。点击 Reject 时，必须先填写意见才能提交。
- **组节点用尽**：组节点达到最大轮数时，使用同样的审批界面。
- **问答**：问答以记录形式显示。等待回答的问题带琥珀色竖线。选项显示为按钮，并带数字键提示。
- **中止**：顶部栏右侧是"Stop run"按钮，文字为红色。
- **续跑**：当运行失败、被中止或预算超限时，运行头部显示 Resume 按钮。如果是预算超限，续跑前可以提高这次运行的预算。

### 10.4 Failure and Uncertainty

- 失败的节点显示红色状态色条和失败图标。抽屉中显示错误信息和最后几条事件。
- 预算超限时，运行头部显示"Budget exceeded"。
- 交互式节点的输入框下方提示：如果平台停止，这个节点会从头开始。
- 校验错误的文案先说明问题，再说明怎样修正。

## 11. Empty, Loading, Error, Success, and Long-Running States

- **空状态**：工作流库为空时，显示"New workflow"按钮，以及两个可以直接打开的示例工作流：aipilot 流程和小说流程。
- **加载**：列表加载时，显示骨架屏。
- **错误**：
  - 校验错误显示在问题列表中，Run 按钮不可用。
  - 节点失败时，节点显示为红色，运行头部出现 Resume 按钮。
- **成功**：运行头部的状态变为绿色，并显示运行摘要。不弹出通知。
- **长时间运行**：运行中的节点和运行头部持续显示已用时间。费用进度条实时更新。
- **等待人工**：节点和运行头部用琥珀色显示等待状态。Inbox 徽标显示等待项的数量。

## 12. Copy and Tone

- 界面文字用英文。
- 语气是工具式的，简洁直接。
- 按钮用动词，并说清结果，例如"Run"、"Add node"、"Send answer"、"Stop run"、"Approve"。
- 状态用短语，例如"Waiting for your answer"和"Pending"。
- 平台不拟人，不说"I'm working on it"之类的话。
- agent 的消息原样显示。
- 错误文案先说明发生了什么，再说明怎样修正，例如："openai/gpt-5 does not support thinking level xhigh. Choose minimal, low, medium, or high."

## 13. Design Acceptance Criteria

### 布局和导航

- **D-1 (导航栏):** 系统应在左侧窄导航栏常驻显示 Workflows、Runs、Inbox 和 Settings 四个图标。
- **D-2 (Inbox 徽标):** 当有问题等待回答或节点等待审批时，系统应在 Inbox 图标上显示等待项的数量。
- **D-3 (创建入口):** 系统应在编辑器左侧显示节点库，并在顶部栏提供"Add node"按钮。
- **D-4 (属性抽屉):** 当用户单击节点时，系统应在右侧抽屉中显示它的属性。画布应保持可见和可操作。
- **D-5 (属性分组):** 系统应把 agent 节点的属性分为 Model、Prompt、Behavior 和 Outputs 四组。
- **D-6 (流程方向):** 系统应让连线从上游节点的底部连到下游节点的顶部。
- **D-7 (缩放控件):** 系统应在顶部栏提供缩小、比例和放大控件，并支持 Ctrl -、Ctrl + 和 Ctrl 0。
- **D-8 (窗口宽度):** 当窗口宽度不小于 1280px 时，系统应完整显示所有区域，不出现重叠。

### 节点、框和连线

- **D-9 (卡片内容):** 系统应在节点卡片上显示类型图标、名称、模型和 thinking level 文字，以及任务文本的前两行。
- **D-10 (卡片底行):** 系统应在编辑器的卡片底行显示所选 skill，在运行视图的卡片底行显示运行状态和用时。
- **D-11 (卡片标记):** 当节点可写、交互式、需要审批或有执行条件时，系统应在卡片右上角显示对应的标记图标。
- **D-12 (容器框):** 系统应把组节点和 foreach 节点画成框，并把子图画在框内。
- **D-13 (foreach 叠层):** 系统应在 foreach 框背后显示两层错开的边线。
- **D-14 (框标题):** 系统应在组节点框的标题栏显示结束条件和最大轮数，在 foreach 框的标题栏显示列表来源。
- **D-15 (折叠框):** 当用户折叠一个框时，系统应只显示框的类型、名称和进度。
- **D-16 (产物标签):** 当下游节点引用直接上游的产物时，系统应在连线上显示产物文件名。
- **D-17 (引用样式):** 系统应用等宽字体和点状下划线显示任务文本中的 `{{...}}` 引用。
- **D-18 (插入引用):** 当用户在任务文本中输入 `{{` 时，系统应列出可用的输入、上游产物和当前项字段。

### 校验

- **D-19 (出错节点):** 当节点有校验错误时，系统应把它的边框显示为红色，并在右上角显示错误图标。
- **D-20 (问题列表):** 当工作流有校验错误时，系统应在画布底部的问题列表中列出每个错误的节点、原因和修正方法。
- **D-21 (跳到节点):** 当用户点击问题列表中的"Go to node"时，系统应把画布移到该节点并选中它。
- **D-22 (禁用运行):** 当工作流有校验错误时，系统应禁用 Run 按钮，并在悬停提示中说明错误数量。

### 运行视图

- **D-23 (只读快照):** 在运行视图中，系统应以只读方式显示启动时冻结的工作流，并标明"Read-only snapshot from run start"。
- **D-24 (状态表示):** 系统应同时用颜色和图标表示节点状态：运行中为蓝色，成功为绿色，失败为红色，等待人工为琥珀色，等待上游和已跳过为灰色。
- **D-25 (状态色条):** 在运行视图中，系统应在每张节点卡片左侧显示 3px 的状态色条。
- **D-26 (运行中节点):** 当节点正在运行时，系统应在卡片上显示旋转图标和已用时间。
- **D-27 (产物进度):** 在运行视图中，系统应把已产出的产物标签显示为带绿色勾的实线，把还没产出的显示为虚线。
- **D-28 (轮次和项切换器):** 在运行视图中，系统应在组节点框的标题栏显示轮次切换器，在 foreach 框的标题栏显示列表项切换器。
- **D-29 (切换器默认值):** 当用户打开运行视图时，系统应默认显示最新的一轮和正在执行的一项。
- **D-30 (运行头部):** 在运行视图中，系统应常驻显示运行状态、已用时间、费用和预算进度、人工介入次数，以及按状态分段的节点进度条。

### 节点详情和人工介入

- **D-31 (详情标签页):** 当用户在运行视图中选中节点时，系统应在抽屉中提供 Events、Task 和 Outputs 标签页。交互式节点另有 Questions，可写节点另有 Diff。
- **D-32 (事件列表):** 系统应把事件显示为每行一条的列表，每行包括时间、类型图标、摘要和用量。
- **D-33 (自动滚动):** 在节点运行期间，系统应自动滚动到最新的事件。
- **D-34 (暂停滚动):** 当用户在事件列表中向上滚动时，系统应暂停自动滚动。
- **D-35 (问答记录):** 系统应按时间顺序显示问答记录。问题左侧有竖线，回答以"You answered:"开头。
- **D-36 (当前问题):** 当交互式节点等待回答时，系统应用琥珀色竖线标出当前问题，并把选项显示为带数字键提示的按钮。
- **D-37 (数字键选择):** 当用户在问答界面按下选项对应的数字键时，系统应选择该选项。
- **D-38 (审批界面):** 当节点等待审批时，系统应在抽屉中显示它的产物和 diff，以及 Approve 和 Reject 按钮。
- **D-39 (拒绝意见):** 当用户点击 Reject 时，系统应显示意见输入框。意见为空时，提交按钮应不可用。
- **D-40 (Inbox 列表):** 系统应在 Inbox 中列出所有等待项，每项显示运行名、节点名、类型和等待时长。
- **D-41 (Inbox 跳转):** 当用户点击 Inbox 中的一项时，系统应打开对应的运行，并选中该节点。

### 状态

- **D-42 (空状态):** 当工作流库为空时，系统应显示"New workflow"按钮和两个可以打开的示例工作流。
- **D-43 (加载状态):** 当列表正在加载时，系统应显示骨架屏。
- **D-44 (节点失败):** 当节点失败时，系统应在抽屉中显示错误信息和最后几条事件。
- **D-45 (续跑入口):** 当运行失败、被中止或预算超限时，系统应在运行头部显示 Resume 按钮。
- **D-46 (预算超限):** 当运行因预算超限停止时，系统应在运行头部显示"Budget exceeded"。
- **D-47 (运行成功):** 当运行成功时，系统应把运行头部的状态显示为绿色并显示运行摘要，不弹出通知。
- **D-48 (重启提示):** 当交互式节点等待回答时，系统应在输入框下方提示：如果平台停止，这个节点会从头开始。

### 视觉和可访问性

- **D-49 (主题):** 系统应提供亮色和暗色主题，并默认跟随系统设置。
- **D-50 (强调色):** 系统应只把墨色强调用于选中状态和主要按钮。界面中其他带色相的元素应只表示状态。
- **D-51 (层级):** 系统应用 1px 边框区分层级，不使用阴影和渐变。
- **D-52 (字体):** 系统应用系统字体显示界面文字，用等宽字体显示模型名、路径、引用、命令、日志和 diff。
- **D-53 (标签大小写):** 系统应用句首大写显示所有标签，不使用全大写。
- **D-54 (界面语言):** 系统应用英文显示所有界面文字。
- **D-55 (键盘焦点):** 系统应为所有可交互的元素显示可见的键盘焦点。
- **D-56 (对比度):** 系统应让文字与背景的对比度达到 WCAG 2.2 AA。

## 14. Open Questions

- **Q-1 (无样稿的画面):** [risk: cosmetic] 工作流列表、运行列表、Inbox 和 Settings 没有样稿。实现时按本规格的布局和视觉系统推出，必要时在实现阶段补一张样稿。
- **Q-2 (连接点的交互细节):** [risk: cosmetic] 节点连接点的位置、悬停样式和拖拽连线的预览没有样稿。
- **Q-3 (大量列表项):** [risk: cosmetic] 当 foreach 有几十项时，标题栏的切换器是否够用，需要在实现后用真实数据检查。
